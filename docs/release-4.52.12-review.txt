Production assessment
Two stable-safe builder fixes are backported from the experimental 4.53.0 line. First, WallBuilderAccess.clearPreparedPlacementTarget() drops a builder's prepared placement target when Workers 2 rebuilds its placement queue after a material runs out, so the builder takes the next block from the fresh queue instead of returning to a block it can no longer place. Second, WallBuilderAccess.clearNextSection(...) is called by NativePerimeterProjects only after a paid next-section handoff is authenticated and immediately before marker creation. It treats the builder intersecting any upcoming target or the reused shovel-site marker box as an obstruction, gathers checked safe standing sites (same-floor space first, then heightmap surface space) that respect recoveryMargin against the whole reservation and do not overlap the marker box, probes them with the existing multi-target createPath/reachedSite logic, retains an unprocessed asynchronous probe for up to 100 ticks, and requests ordinary navigation to the proven-reachable site. It never teleports, edits blocks, or changes the plan, and it declines to move while riding, leashed, fighting, holding another native area, or while an existing native path is running. ConstructionMarkerSite and markerBox became public for this cross-package read; their behavior is unchanged. Finite chest supplies, native supply requests, payment, accepted plans, claims, and dependency metadata are unchanged.

Findings disposition
Copilot (d66de15): the selected clearance destination could be the marker itself, which marker creation rejects. Fixed in 47a7bbf by excluding candidates whose body box intersects the marker box. Codex (47a7bbf): a builder already inside the marker box but outside every target was not moved; and a partial path toward an unreachable nearest site could be retried forever. Fixed in 981e194 by counting marker-box overlap as an obstruction and by using the multi-target reachability probe, never walking partial paths. Codex (981e194): unprocessed asynchronous probes were discarded each controller tick; and an indoor shovel site only offered heightmap roof positions. Fixed in 771af9e by retaining pending probes for up to 100 ticks and offering loaded same-floor standing space before surface positions. Each fix carries a named regression in WallBuilderAccessTest or BuilderArrivalDispatchTest, and the two new BuilderArrivalDispatchTest cases were confirmed red before the production change.
